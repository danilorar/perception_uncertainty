HiDrive AEB 是怎么接进 Studio 的

注意（2026-10-20）：本页描述的是已停用的 esmini 2.40 接入方式。控制器现已移植到 esmini 3.8.1 接口，源码放在 AEB Controler (esmini 3.8.1)，由 hidrive/build.py 编译进隔离的 esmini-hidrive-v3.8.1。现行说明见 hidrive/README.md 与 hidrive/MIGRATE-3.8.1.zh.md；下文的行号链接指向旧的 2.40 源码树。

一共分两层：先把控制器编译进一个独立的 esmini 2.40 程序，再让 Studio 调用这个程序跑老师的场景，并把输出转换成 Studio 原有的格式。控制器源码全程没有被修改，也没有被 AI 阅读。

点击文件名或函数名，会用本机 VS Code 打开对应文件并跳到那一行。队友请把路径改成自己电脑上的项目文件夹；esmini 2.40 的文件要先运行一次 hidrive/build.py 才会存在。

Studio 平时用的 esmini 3.8.1 程序库里没有这个控制器，所以 HiDrive 走一条单独的路：Studio 不再自己一步步推进仿真，而是把整个场景交给 2.40 程序跑完，然后读取它的结果。

第一层 · 编译

把控制器编进 esmini 2.40

控制器是按 esmini 2.x 的接口写的，放进 3.8.1 编译会失败，所以单独下载了 esmini v2.40.0（提交 c5f50c7），放在 esmini-lab/runtime/esmini-hidrive-v2.40.0/。

esmini 要认识一个新控制器，需要改它公开的源码，一共三处。另外 CMakeLists.txt 有两处小改动，只是为了不去下载用不到的测试数据和外部依赖。

esmini 2.40 中的文件改了什么作用
Controllers/ControllerHiDrive.*从 AEB Controler/ 原样复制进来Controllers 目录下的 .cpp 会被自动加入编译
Controllers/Controller.hpp控制器类型枚举里加一项 CONTROLLER_TYPE_HIDRIVE控制器头文件会用到这个类型编号
ScenarioReader.cpp加 #include "ControllerHiDrive.hpp"让场景读取器能看到控制器
ScenarioReader.cppLoadControllers() 里加一行注册场景里写 HiDriveController 时，esmini 就会创建它
 
// ScenarioReader.cpp
void ScenarioReader::LoadControllers()
{
    RegisterController("HiDriveController", InstantiateControllerHiDrive);
    ...

注册用的名字 "HiDriveController" 和老师场景文件里写的一致，所以场景文件本身不用改：

<!-- DATA/C_original_1549178.xosc，object_1 = 自车 -->
<Controller name="HiDriveController">
  <Property name="timeGap" value="1.0" />
  <Property name="mode" value="additive"/>
  ...

编译怎么做

simulation-studio/hidrive/build.py 把上面这些步骤合成了一条命令：

  1. esmini 2.40 源码不存在时，从 GitHub 下载 v2.40.0。
  2. 按 ENGINE_EDITS 列表修改公开文件。已经改过的会自动跳过，重复运行也安全。
  3. 从项目已有的 esmini 3.8.1 完整安装里复制 OSG / OSI / SUMO 依赖包，不用重新下载。
  4. 用 shutil.copy2 复制两个控制器文件，只复制，不打开。
  5. CMake 配置并编译 esmini 目标（Release, x64），完成后把 exe 复制到 bin/esmini.exe。
cmake -S esmini-hidrive-v2.40.0 -B build -A x64 -DUSE_OSG=ON -DUSE_OSI=ON -DUSE_SUMO=ON \
      -DUSE_GTEST=OFF -DDOWNLOAD_EXTERNALS=OFF ...
cmake --build build --config Release --target esmini

编译输出只写进 esmini-lab/evidence/hidrive-build.log，不在终端显示，因为编译报错可能引用控制器源码。增量编译大约 6 秒，第一次完整编译要几分钟。

关键的坑：没有画面就崩溃

编译成功后，用常见的无窗口参数 --headless 跑场景，程序在仿真时间约 0.05 s 时直接退出，日志里没有任何错误。换了三种时间步长（0.05 / 0.01 / 0.001 s）都在同一时刻崩溃，打开画面窗口就能完整跑完 10 s。由此判断控制器在用画面（viewer）对象，没有画面时就访问了空指针。

解决办法来自 esmini 2.40 的公开源码：

  • playerbase.cpp：只要命令行里有 --window，就会创建 viewer。
  • viewer.cpp 的 InitTraits()：如果同时有 --headless，就设置 traits->pbuffer = true，也就是在显存里离屏渲染，不在桌面上开窗口。

所以两个参数一起用，控制器拿到了它需要的 viewer，桌面上也不会弹窗。控制器和引擎都不用改。

esmini.exe --osc scene.xosc --headless --window 0 0 320 180 ...
第二层 · 调用

Studio 怎么调用它

核心是新文件 simulation-studio/hidrive_runner.py 里的 run_hidrive()，每次运行按顺序做这些事：

  1. check_build()：确认 bin/esmini.exe 存在；比较 AEB Controler/ 里的文件和编译用副本的大小与修改时间，不一致就报错，提示先重新编译。
  2. build_hidrive_scene()：把老师的场景复制到本次运行目录，只把道路和车辆目录改成绝对路径，HiDriveController 和它的参数原样保留。
  3. 启动 2.40 程序，参数包括上面的 --headless --window、Studio 设置的时间步长 --fixed_timestep、碰撞检测 --collision，以及两份输出：--csv_logger 和日志文件。
  4. read_esmini_csv()：读 esmini 的 CSV，得到每一帧每辆车的位置、速度、朝向、包围盒和碰撞对象。
  5. read_log_values()：读日志里控制器自己打印的 LOG_VALUE:AEB_active 和 LOG_VALUE:Acceleration，分别作为"AEB 触发"和"指令加速度"。
  6. 转换成 Studio 的标准文件：ego.csv、truth.csv、observations.csv、metrics.csv。最小间距和 TTC 用真实位置计算。首次碰撞的那一帧之后就截断，和原生 ACC 的规则一致。
  7. 交给已有的 finish_run()：生成曲线（plots.py）和 MP4（video.py 用 esmini 3.8.1 回放 truth.csv）。

日常怎么用、什么时候要编译

跑实验

不需要编译。在 Studio 里把控制器选成 HiDrive AEB，再点"运行新模拟"。

控制器文件改了

在 simulation-studio 目录运行一次：

.venv\Scripts\python.exe hidrive\build.py

新电脑第一次用

先装好 esmini 3.8.1 完整版和 Visual Studio C++ 工具链，再运行同一条 build 命令，它会自动下载 2.40 源码。

目前的限制

  • 感知误差加不进去。控制器用的是自己内部的感知，Studio 的 OU 测距误差到不了它，所以选 HiDrive 时只能用理想探测。要加误差，得先知道控制器从哪个接口读取前车距离。
  • "AEB 触发"和"加速度"来自控制器自己写进日志的数值；位置、速度和碰撞判断来自 esmini 的真实状态。
  • 引擎是 esmini 2.40，和 Studio 其余部分用的 3.8.1 不是同一版本。视频回放仍然用 3.8.1。
  • 自车速度曲线开头的小锯齿来自老师轨迹文件本身的坐标精度（0.01 m），不是控制器造成的。
三个老师场景的结果：1549178 和 1554254 没有碰撞，AEB 分别在 3.31 s 和 3.20 s 触发；1554431 在 3.23 s 触发，5.49 s 时以 34 km/h 撞上前车。
